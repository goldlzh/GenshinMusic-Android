# GenshinMusic-Android：原神 MIDI 触摸演奏工具

Android MIDI 演奏工具，将 MIDI 文件或 USB 电子琴输入转换为原神乐器的触摸输入。基础编曲和播放规则与[电脑版 GenshinMusic](https://github.com/goldlzh/GenshinMusic)对齐，手机通过无障碍服务输出触摸。两个平台独立构建和发布；电脑版的演奏可视化、选段转调及区域播放目前属于桌面功能。

当前版本 **1.3 / 版本代码 4**，最低 Android 8.0（API 26）。手机端最多同时保持 **10 个不同琴键**，超限时先释放最早按下的旧音；电脑版不增加复音上限，仍使用原有 21 键映射。

## 安装与开始使用

从 [GitHub Releases](https://github.com/goldlzh/GenshinMusic-Android/releases/latest) 下载 `GenshinMusic-Android-v1.3.apk`。公开仓库和安装包不包含 MIDI 曲库、个人校准、歌曲记忆或签名密钥，安装后自行导入 MIDI。

应用 ID 保持 `com.example.lyretest`，发布 APK 沿用本机原有调试签名，兼容现有普通版安装。覆盖安装可保留校准、曲库和歌曲记忆；不要先卸载旧版。当前提供调试签名构建，尚未配置独立发布签名。以后自行重新构建产生的签名通常不同，不能直接覆盖这里的安装包。

本地开发目录中的历史 APK 和内置 172 首版仅保留在本机，不上传至公开仓库。内置版应用 ID 为 `com.example.lyretest.songs172`，与普通版不同。

1. 在“使用前设置”中开启无障碍服务，设置后台保活并完成 21 键校准。
2. 在“曲库”中导入或选择 MIDI，按需调整速度、起点和编曲参数。
3. 点击“开始演奏”，选择 5 秒或 10 秒准备时间，切回原神并打开乐器。
4. 使用悬浮条暂停、继续、切歌、跳转进度或插入标签。实时电子琴的连接与设置见下文。

首页按以下五个区域折叠，默认仅曲库展开，并记住各区域的展开状态。曲库列表支持独立滚动和点选。

| 区域 | 内容 |
| --- | --- |
| 使用前设置 | 无障碍、后台保活、键位校准、日志导出、触摸兼容模式、悬浮条尺寸 |
| 演奏选项 | 速度、起点、标签、歌曲记忆、音长模式和高级编曲、播放顺序、开始与停止、分析报告 |
| 曲库 | 导入、删除、排序、搜索、选歌与前后切歌 |
| 实时电子琴 | USB MIDI 连接、即插即弹、合并窗口、移调、折叠、松键和踏板 |
| 教程 | 校准示意图和使用说明 |

## MIDI 文件演奏

### 音长模式

在“高级编曲参数”中选择模式并应用：

| 模式 | 主旋律 | 单音伴奏 | 和弦伴奏 |
| --- | --- | --- | --- |
| 固定短按 | 40 ms | 40 ms | 40 ms |
| 原谱音长 | 按 MIDI 时值 | 按 MIDI 时值 | 按 MIDI 时值 |
| 旋律长音 | 按 MIDI 时值 | 40 ms | 40 ms |
| 和弦长音 | 40 ms | 40 ms | 按 MIDI 时值 |

新歌曲默认“原谱音长”，歌曲踏板默认关闭。旧版六项编曲设置迁移为手动记忆，音长模式保持固定短按，以便升级后继续使用原先效果。

“和弦长音”只认可原速 15 ms 窗口内至少两个不同的可映射伴奏键，不把主旋律、无法演奏的音或折叠后的重复键凑成和弦。和弦识别不随倍速改变，各音保留起音先后；同键与主旋律重合时优先短按。

解析器配对 `note_on` 与 `note_off`，也接受零力度 `note_on` 作为松键。跨速度变化的音长按速度表换算；无松键的音回退为 250 ms。勾选“跟随 MIDI 延音踏板”后，仅延长当前模式允许长按的音。

### 时间轴、通道与转调

- 速度范围为 **0.5～2.0 倍**。起音、组内偏移和原谱音长随倍速缩放，固定短按保持 40 ms。同键重触发留 10 ms 松开间隙；与下一拍冲突时可缩短前音。
- 同时同键音符合并；折叠后的伴奏不打断正在保持的同键主旋律。此处的同键处理独立于下文的十音限流。
- 首音归零，只压缩所有键都已松开后的长空白；有长音或踏板保持时不当作空白。总时长包含最后一次松键。
- 编曲不再使用旧版的 80 ms 伴奏冷却、近同时音强制齐奏和密集发音组平滑。报告仍可用 80 ms 分组统计；触摸手势也单独按最多 80 ms 分片，并保留片段内的准确偏移。
- 自动保留通道优先按音符数量；数量并列时，按合并时间轴首次正力度 `note_on` 的顺序选择。同一 tick 保留物理轨及轨内事件顺序。
- 手动指定的旋律轨被通道筛选排除后，回退到剩余音轨中平均音高最高的一轨；“只弹旋律”沿用此结果。
- 开启和关闭八度折叠分别计算推荐转调。自动推荐采用当前折叠开关对应的结果，报告同时展示两种建议和当前实际可奏数量。
- 推荐转调依次考虑主旋律可奏数、旋律音程变化、同键重叠冲突、伴奏可奏数、折叠量和转调幅度。手动转调支持 −48～+48 半音。

暂停、停止、跳转和切歌都会终结旧触点。普通暂停或悬浮条交互结束后，只恢复此前成功发出且仍在持续的音；中途起播或跳转不补按目标之前已开始的长音尾部，目标处及之后的新起音仍正常演奏。向后跳转允许重新演奏后续起音。多个播放实例与实时电子琴共用输入锁。

### 歌曲记忆与播放顺序

每首歌独立记忆通道、主旋律音轨、转调、折叠、扫音、只弹旋律、音长模式、踏板、速度和演奏起点。

- **自动记忆**：准备时间结束、播放器正式开始时保存实际参数与起点。解析、取消准备、暂停、继续、拖动和停止不更新最近播放时间。
- **手动记忆**：点击“保存手动记忆”立即保存，无需先演奏。恢复时手动优先；临时演奏仍独立更新自动记忆。可主动恢复或清除手动记忆。
- 新歌恢复默认参数，不沿用上一首设置。迁移旧设置时，速度采用原全局速度并限制到 0.5～2.0。
- **首字母 A–Z**：中文使用手机内置 ICU 拼音转换，英文忽略大小写，数字和符号排在字母之后。少数多音字可能与电脑拼音库不同。
- **添加时间**：最近添加在前。旧歌曲首次初始化采用文件修改时间作近似值，之后固定保存；新导入使用导入时间。
- **播放时间**：最近一次正式开始播放的日期和时刻，最近在前，未播放的在后；不记录次数或累计时长。主界面显示添加与最近播放时间。
- 顺序播放到队尾停止；单曲循环恢复本曲记忆；随机播放尽量避免连续重复。手动上一首／下一首可循环，切歌准备时间为 3 秒，首次播放可选 5／10 秒。
- 起播时固定本轮队列，“最近播放”重排不会打乱队列；主动切换排序会更新后续顺序。搜索只筛选列表。

歌曲记忆、标签和时间信息保存在 App 私有设置中。电脑与手机使用各自的曲库和配置，不会自动互传歌曲或标签。

### 标签与悬浮条

悬浮条保留暂停、关闭和进度条，并提供独立的“上一首 / 插入标签 / 下一首”操作行，最小宽度下也保留该行。

在游戏中点击“插入标签”，按当前歌曲和实际进度保存“标签 1、标签 2……”而不弹出输入框。回到主界面的“标签 / 起点”，可以设为下次起点、跳转当前歌曲、重命名、删除，或移动到当前演奏进度；未演奏时移动到选择的起点。

标签按整曲进度比例保存。手动或自动记忆可关联标签 ID：改名不影响起点，移动后跟随，删除后保留删除前的位置。修改音长模式、折叠等参数可能改变总时长，必要时重新调整标签。

## USB MIDI 实时电子琴

支持 USB OTG 设备选择、即插即弹、移调、折叠和 5／10 秒准备时间。

- **跟随松键**和**跟随延音踏板**默认开启：按住持续保持，松开释放；踩住踏板时，松键后继续保持。
- 关闭松键跟随后，每次起音固定短按约 40 ms，按压时长和踏板都不会延长。开启时，极短触键也有约 40 ms 最短发音保护。力度不影响游戏触摸。
- **合并同时按下的音符**默认开启，窗口为 30 ms，可设置为 0～200 ms 的整数；0 或取消勾选表示关闭。
- 从首个可演奏音符到达时刻计算固定窗口，不因后续按键无限延长。只合并起音，松键、踏板和全部松键指令独立处理；已有长音时也可合并新和弦。
- 合并窗口结束前已松开的短触键，触发后仍保留至少 40 ms。两端参数在下一次连接时生效，实际输入另受系统调度影响。

实时电子琴的松键规则独立于 MIDI 文件的四种音长模式。触点不足时，下文的最早音释放规则优先于长音与最短音长保护。

实时演奏只在原神前台输出。退出游戏前台、设备断开、停止或方向改变会结束会话并释放触点；重新连接后只接受新消息。手动停止暂时停用自动连接，可通过手动连接或重新开启即插即弹恢复。

## 手机端触点上限与续接

文件播放、实时 MIDI、手势分片和续接层统一使用最多 **10 点**预算；若系统每批路径上限更低，则使用更低值。第 11 个不同琴键起音时，先释放仍在按住且起音最早的琴键，再接纳新音。连续超限时依次释放旧音，主旋律和伴奏遵守相同规则；自然结束的音先腾出位置。

- 文件播放提前截短被替换音的结束时间，暂停后不会恢复被截去的尾部。同刻起音采用时间轴的稳定键序；同刻新音本身超过 10 个时，保留排序靠后的 10 个并删除零长度音。
- 实时 MIDI 按实际起音时间处理，同刻按消息接收顺序处理。先提交 1 ms 旧音释放片段，再接纳新音；单次到达超过 10 个不同键时依次分帧处理，最后保持最新 10 音。
- 被替换的按住音、踏板延音不会因空位出现或踏板变化自动重响。旧 `note_off` 仍对应原来的 `note_on`，避免误松后来重新按下的同音。折叠到同一琴键的多个来源共用一个触点。

Android 使用 `continueStroke` 保持长触点，让不同音符分别松开。续接在同一琴键内来回移动 1 个物理像素，产生有效 MOVE；有旧触点时，新触点最早从第 1 ms 加入。只有系统完成回调后才提交续接状态，未提交或被交互取消的批次不记作已成功按下。

已被取消或超时的输入不自动重放：播放器停止、释放触点、关闭播放悬浮条并提示输入中断；只有从未提交成功的批次才尝试其它提交线程。悬浮条按下、拖动和按钮操作会暂时让出触摸输入，手动暂停状态保持独立。

持续触摸的指针预算耗尽时，需要结束并重建剩余触点。因此极密集连续长音段中的保留音可能重新触发，运行日志会记录；优先利用自然全部松键的空隙重置预算。重建时排除已经完成的旧音终结项，避免将已释放的音误当新音再次按下。

`GestureDescription.getMaxStrokeCount()` 表示每批手势的路径总数，不等同于实际同时触摸能力。1.2 的 20 点预算仅为历史实验，不能据此认为系统支持 20 点并发，当前已由十音规则取代。相关依据：[Android 手势 API](https://developer.android.com/reference/android/accessibilityservice/GestureDescription#getMaxStrokeCount())、[AOSP GestureDescription](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/core/java/android/accessibilityservice/GestureDescription.java)、[MotionEventInjector](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/services/accessibility/java/com/android/server/accessibility/MotionEventInjector.java)、[原生输入定义](https://android.googlesource.com/platform/frameworks/native/+/master/include/input/Input.h)、[InputDispatcher 校验](https://android.googlesource.com/platform/frameworks/native/+/refs/heads/main/services/inputflinger/dispatcher/InputDispatcher.cpp)。

## 项目结构与开发

| 路径 | 用途 |
| --- | --- |
| `app/src/main/java/com/example/lyretest/` | 界面、MIDI 解析与编曲、播放、实时输入、触摸续接、曲库与设置 |
| `app/src/main/res/` | Android 界面资源与服务配置 |
| `app/src/test/` | 单元测试及电脑版导出的时间轴参考数据 |
| `ref_python/GenshinMusic/` | 可选本地参考副本，不入库；其中 `songs/` 用于自备曲库构建和曲库对照测试 |
| `artifacts/` | 本地当前及历史安装包，不入库；公开安装包见 Releases |
| `artifacts/analysis/` | 本地 MIDI 曲库统计与分析资料，不入库 |
| `gradle/`、`gradlew`、`gradlew.bat` | Gradle Wrapper |
| `app/build/`、`build/`、`.gradle/`、`.kotlin/` | 构建产物与缓存 |
| `.idea/`、`local.properties` | IDE 与本机 SDK 配置 |

在 Android Studio 中打开项目，或在项目根目录运行以下 PowerShell 命令。使用已安装的 Android Studio JBR；路径不同时调整 `JAVA_HOME`：

```powershell
$env:JAVA_HOME = 'C:\Program Files\Android\Android Studio\jbr'
$env:GRADLE_USER_HOME = Join-Path $env:USERPROFILE '.gradle'
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebug --no-configuration-cache --console=plain
```

依赖已缓存时可加 `--offline`。普通版输出为 `app/build/outputs/apk/debug/app-debug.apk`。需要自备曲库构建时，把自己的 MIDI 放入 `ref_python/GenshinMusic/songs/` 后运行 `:app:assembleBundled`，输出为 `app/build/outputs/apk/bundled/app-bundled.apk`。只有 `bundled` 构建打包该目录，`debug` 和 `release` 不内置 MIDI。

公开仓库保留 `app/src/test/resources/desktop_cases.tsv` 中的 576 组合成时间轴参考场景，由电脑版的 `tests/export_android_fixtures.py` 生成。真实曲库及对应 `desktop_corpus.tsv` 不入库，缺少时自动跳过两项可选曲库测试，其余单元测试照常运行。需要真实曲库对照时，可在本地准备曲库并用电脑版脚本重新生成参考数据。

## 验证与版本记录

发布前验证：本地自备曲库环境 **92 项 Android 单元测试通过**；只含公开源码的独立目录 **90 项通过、2 项可选曲库测试跳过**，并成功构建普通版 APK。公开 APK 与原 1.3 普通版相同，签名验证通过。覆盖连续超限、最早旋律被替换、同刻多音、实时消息顺序、踏板与折叠同键、旧松键事件、文件及实时状态到触摸续接的组合流程，以及重建不重放已结束音。

保留 **576 组跨端时间轴场景**和 **172 首真实 MIDI 曲库对照**，检查四种音长模式、折叠、踏板及 0.5／1／2 倍速；同时覆盖 5 点和 10 点预算的文件手势规划、500 次长音续接、同键重触发、暂停跳转、输入互斥、标签记忆和排序。

尚未进行真机游戏输入与实体电子琴音效验证。实测时可先使用同一首歌、相同参数对照电脑版，再检查实时长音与新和弦、分别松键、踏板、0／30／80 ms 合并窗口，以及暂停、进度条和标签操作。
